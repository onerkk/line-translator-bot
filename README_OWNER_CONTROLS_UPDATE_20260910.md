# 發起人／管理員按鈕權限更新

版本：`2026-09-10.4-owner-only-controls`

本包接續 `line-translator-silent-ack-update-20260910.zip`，只包含本次修改的檔案。依原相對路徑覆蓋專案，再重新部署並重啟所有程序。

## 本次規則

| 功能 | 發起人／機器人管理員 | 其他人 |
| --- | --- | --- |
| 查看回覆 | 主動點擊時顯示一則精簡文字狀態；不重送整張通知、不產生原生 @ 標記 | 不回應、不新增查閱紀錄 |
| 停止提醒 | 靜默停止該通知，後台記錄停止者 | 不回應、不修改通知 |
| 照片詢問「翻譯這張」 | 原照片發送者或管理員可啟動翻譯 | 不回應、不取走圖片、不建立翻譯工作、不呼叫 AI |
| 舊照片卡「跳過」 | 原照片發送者或管理員可靜默取消 | 不回應、不移除圖片 |
| 了解 | 維持依被標記名單記錄回覆，已回覆者不再被提醒 | 名單外回覆仍不記錄 |

管理通知不要求發起人或管理員在被標記名單內。此處管理員使用程式既有的身分設定：後台 `admin_users.is_admin` 或 `BOOTSTRAP_ADMIN_USER_IDS`；不以按鈕參數、姓名或「被標記」身分判定管理權限。

所有操作都必須來自原通知／照片所在的聊天室。管理員也不能拿其他群組的按鈕識別碼跨群操作。

## 介面

- 移除「了解」下方的「說明／Jelaskan」按鈕及說明文字。新確認卡、快捷選單與預覽不再顯示該按鈕。
- 「查看回覆」恢復原名稱；只有發起人或管理員主動查詢時才顯示精簡結果。
- 停止提醒不發「已停止」或「沒有權限」提示，避免洗畫面。
- 已經送到 LINE 的舊卡片外觀不會自動改寫；舊按鈕會使用新的後端權限檢查，不會為更新外觀而重發卡片。舊說明按鈕的相容處理仍只記錄原有名單內的回覆。

## 修正重點

原照片詢問流程只檢查圖片是否尚未過期，接著就發進度訊息、取走圖片，沒有檢查點擊者及原聊天室。現在先查驗儲存的原照片發送者與聊天室，取得檔案鎖後再檢查一次；未授權點擊不會影響他人的圖片。只有成功取得處理權的人會啟動翻譯與進度提示，重複點擊不再重複啟動。

管理員代按照片翻譯時，正常工作與失敗重試都保留原照片發送者及原聊天室。通知的查看／停止也會在原子更新時重新檢查權限，防止權限撤銷後仍寫入。

了解的靜默記錄、被標記名單、後台設定的提醒間隔、僅標記未回覆者、零未回覆自動停止，以及翻譯、OCR、表單、分享等既有流程保留。

## 驗證

- 新增 62 個權限與流程測試，包含真實簽章驗證的本機 webhook、發起人、管理員、bootstrap 管理員、一般成員、跨群組、過期卡、重複點擊、並行點擊及權限撤銷。
- 完整離線回歸：**2,402 passed，443 subtests passed**，62.53 秒。
- 後台及使用者頁面操作測試全部通過，包含查閱紀錄、停止提醒、名單、表單、分享、群組選單及頁面切換。
- 翻譯資產驗證、管理後台 JavaScript 語法檢查通過。

測試使用暫存 SQLite、模擬 Redis、假 LINE／AI 傳輸及本機頁面；離線執行器封鎖對外 HTTP、DNS 與 socket。未向真實群組發送測試訊息，也未進行正式部署。

## 官方依據與部署確認

[LINE 官方 Postback action 文件](https://developers.line.biz/en/docs/messaging-api/actions/#postback-action)（2026-09-10 查閱）說明按鈕可只把事件送到伺服器，聊天顯示文字是可選設定。本次保留不帶聊天顯示文字的按鈕，未授權事件不呼叫回覆或推播 API。

登入後台後，`/api/admin/factory/receipts?group_id=群組ID` 的 `build_id` 應為 `2026-09-10.4-owner-only-controls`。若仍是舊值，代表該程序尚未載入更新；需確認實際部署使用的檔案及所有工作程序版本。
