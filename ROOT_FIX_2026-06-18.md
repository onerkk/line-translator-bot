# v3.24 Target-language purity root fix

## Root cause

The Chinese-target validator treated a Latin word as acceptable whenever that word also appeared in the source. That rule was intended to preserve machine codes, but it also allowed ordinary Indonesian words such as `BOLEH` to survive inside Chinese output. The previous long-run detector only rejected four or more Latin words, so a single leaked word passed validation and could be cached.

## Architecture change

- Replaced source-presence permission with a target-language purity classifier.
- Only immutable identifiers, explicit target-side glossary terms, technical/model codes, and probable proper names may remain in a Chinese translation.
- A single ordinary Indonesian/English word now causes a hard validation failure.
- Failed ordinary messages receive one source-grounded review instead of being silently dropped.
- Failed critical announcements receive a fresh whole-document retry from the source.
- Lexical TM and Vector TM early-return results now pass the same deterministic integrity gate, so stale cached translations cannot bypass the fix.
- Repeated `source phrase (中文術語)` patterns are inferred as runtime terminology pairs. A single occurrence is not promoted, preventing weak guesses.
- Translation and review prompts explicitly prohibit untranslated source words and redundant `literal translation（中文術語）` duplication.

## Regression coverage

`test_translation_quality_gate.py` covers:

1. `不BOLEH使用` is rejected.
2. Clean Traditional Chinese passes.
3. `BF3`, `SOP`, `LINE`, `OpenAI`, and `Taipei` remain allowed.
4. `BOLEH` is not misclassified as an all-caps machine code.
5. Non-critical output is source-grounded and repaired.
6. Critical output is freshly retried from the source.
7. Repeated `kondom pelindung (套罩)` is inferred as `kondom pelindung => 套罩`.
