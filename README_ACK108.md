# 更新 108：作業確認啟用設定修正

本包接續第 107 版，只包含本次變更檔案。沒有重設既有群組、提醒與翻譯設定。

## 問題與修正

已重現：後台儲存「輸入 /ack 或 /確認 指令才建立」後，若「了解」快捷鍵被關閉、移除，或只勾圖片用途，舊程式仍可能回覆「未啟用作業確認」。程式將快捷鍵顯示條件連帶當成指令啟用條件。

修正後，作業確認只依「作業確認觸發方式」判斷。指令模式固定提供「了解」按鈕，保留自訂名稱；移除該快捷鍵時，確認卡使用預設名稱。底部選單與文字／圖片快捷鍵依原設定顯示，不會因建立確認卡而重新啟用。沒有重新加入「不了解」按鈕，一般翻譯仍不自動建立確認卡。

關閉或移除快捷鍵後，既有確認卡仍可回覆，未回覆提醒仍依原間隔持續運作。選擇「關閉作業確認」並儲存，才會停用指令及後續提醒。若只想關閉提醒、保留確認卡，請在「工廠工具」取消「自動 @ 提醒尚未回覆的人」。單筆通知仍可按「停止提醒」。

## 套用

1. 將 ZIP 解壓縮，依原路徑覆蓋第 107 版專案。`static/admin_quick_reply.js` 必須放在 `static/`；`tests/unified_menu_ui_smoke.cjs` 必須放在 `tests/`。
2. 部署並重新啟動所有機器人程序，再重新開啟管理後台。本次也更新後台 JavaScript 的載入版本。
3. 在「快捷鍵」選擇正確群組，確認模式為「輸入 /ack 或 /確認 指令才建立」。若調整設定，請按「儲存此設定」。群組獨立設定優先於全群組預設。
4. 在原群組輸入 `/ack 請確認設備已停機` 或 `/確認 請確認設備已停機`，即可建立帶「了解」的確認卡。

不需清空資料或重建通知。`line_ack_reminders.py` 的介面版本沒有改變，本次未重送該檔案。第 107 版的翻譯品質、重試與速度修正保留。
